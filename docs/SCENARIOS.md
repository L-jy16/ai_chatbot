# 채팅 시나리오 계약

현재 서비스는 C의 모드 번호 `q1/q4/q5/q6/free`를 사용한다. 화면의 `data-mode`, `POST /api/chat`의 `mode`, 새 `chats.mode`는 같은 값을 사용한다. B가 제공한 트렌드 조회는 Q1과 Q4 타이밍 분석에 연결한다.

| 모드 | 화면 기능 | 서버 처리 |
| --- | --- | --- |
| Q1 / `q1` | 오늘의 주제 | B의 뉴스와 최근·과거 검색 추이를 참고해 오늘의 숏폼 주제를 추천한다. |
| Q4 / `q4` | 타이밍 체크 | B의 검색 추이·뉴스를 이용해 지금 올리기·기다리기·다른 각도를 판단한다. `keyword`는 선택 입력이다. |
| Q5 / `q5` | 새로운 각도 | C의 반전·비교·논쟁·정보·경험 관점에서 5~10개 아이디어와 추천 1개를 제안한다. |
| Q6 / `q6` | 다음 편 기획 | C의 1→2→3편 구조와 오늘 올릴 편을 제안한다. 기존 주제가 없으면 먼저 묻는다. |
| 자유 질문 / `free` | 일반 기획 대화 | 자료가 없을 때 최신 추세를 지어내지 않고 답한다. |

Q6 화면의 이전 업로드 주제 입력은 선택 사항이다. 입력하면 `최근 업로드 주제: ...\n질문: ...`를 하나의 `message`로 보내며 전체 500자 제한을 적용한다. 입력하지 않으면 현재 질문과 성공한 이전 대화에서 주제를 찾고, 없으면 질문하도록 프롬프트에 지시한다.

뉴스 검색 결과는 최신순 일부이며 인기 순위가 아니다. 검색 추이는 상대 지수이고 유튜브 조회수가 아니다. 자료가 없거나 조회에 실패하면 그 한계를 밝혀야 한다. 실제 AI 답변의 사실성과 키 권한은 별도로 확인한다.

## 기존 기록

`chats.scenario_version`은 번호 체계를 구분한다. 기존 C 기록은 버전 1, B의 Q1~Q5 번호로 저장된 기록은 버전 2, 현재 C 계약으로 새로 저장한 기록은 버전 3이다. 기존 테이블에 열이 없으면 시작할 때 기본 1로 추가한다. 기록 API는 버전 2의 `q3/q4/q5`를 화면 표시용 `q4/q5/q6`로 바꾼다. 원본 DB의 값은 수정하지 않는다. 버전 2의 `q2`는 현재 선택 모드에 대응하지 않으므로 기록에서 이전 운영 채널 추천으로 표시한다.
